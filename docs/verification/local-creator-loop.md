## What is observed, proposed, and still required

Read-only inspection on October 7, 2026 found the local backend using an
image-owned compiled server and a read-only host contract mount. The image's
revision label identifies the base checkout, not uncommitted feature code.
The creative schedule is every fifteen minutes. Its trigger says to make a
saved artifact every cycle, inspect the previous project, and avoid beginning
with a Discord or web search. The maker's allowlist admits its own Bluesky
feed/profile/publication and Discord sending, but excludes most perception and
memory tools. The conversational head separately prioritizes quick replies and
does not interrupt the maker.

These are deployment facts, not proof of the complete cause of repetitive
outputs. Earlier runtime records showed repeated self summaries, empty memory
hydration, and no social perception calls in the sampled completed cycles.
Those observations support the need for an independent perception path and
meaningful recall; they do not establish that every historical cycle lacked
external information.

The source implementation now connects scheduled `:actions/character-intake`
to existing authorized social read closures and OpenPlanner event ports. Maker
and reply turns reload bounded admitted encounters before assembling their
decision input. Fixture coverage checks retry, refreshed authority, and
reconstructing ports over retained rows. **The host overlay has not been
changed: consumed source settings and fixtures do not establish deployed
intake, natural decisions, or a complete continuous creator personality.**

## Scoped graph recall and the automatic prompt

The host loads bounded eligible encounters before the final prompt cap,
reauthorizes each source around reads, and checks the complete source binding
after loading. A source revoked during a later source read refuses that held
snapshot. The owning Mongo adapter refreshes the descriptor after its index,
embedding and graph reads. These observations do not establish atomic grant
reservation or distributed fencing.

The automatic turn passes the host callback to passive hydration. The Mongo
client invokes the released owning graph reader over its existing SDK handle;
the consumer validates the owning result contract through the named extern
adapter. An unsupported port, malformed result or transport failure remains a
distinct failed graph outcome with no vector-only substitution. Indexing-pending
and denied states remain distinct. Graph-only neighbors include stable node and
edge paths in the actual provider-session message as quoted untrusted encounter
material. `field-status: not-loaded` explicitly preserves the unfinished physical
field link; recall performs no reinforcement write.

The graph prompt fixture runs `hydrate-and-materialize!`, the actual Mongo client,
named extern adapter and released OpenPlanner selection code over held SDK
collections, then captures `IAgentSession/send-user-message!`. The host authority
fixture separately exercises canonical stored principal/source/account resolution.
Together these establish source-level integration, not live Mongo/model behavior,
automatic artistic choices, physical field persistence or consumed mood.

The original bare REST graph fixture remains in committed RED evidence. Its
response was a transport placeholder, not privacy or traversal proof. The refined
fixture retains the original neighbor/inclusion/failure assertions and adds the
real owning path. Its session visibility assertion is an independent preserved
conversational precondition, not authority to read the character graph.

## Stable character and memory ownership

Mode selection changes exposure, not identity or memory ownership. The accepted
configuration keys are `:agent :tool-modes` and `:agent :character-context`, with
top-level fallbacks supported by the implementation. A supplied character
context is:

```clojure
{:identity "an existing resolved character identity"
 :persona "the existing resolved personality text"
 :snapshot {}               ; actual supplied field projection, if available
 :evidence-ids []            ; actual retained evidence identities
 :revision "optional existing projection revision"}
```

The example describes the shape; its placeholder identity and persona are not
deployment values. The supported default derives identity from the resolved
actor/contract and persona from its existing resolved prompt. Empty snapshot
and evidence vectors explicitly mean that no field projection was loaded;
they do not mean the character's mood or relationships evolved. A real supplied
projection must retain its existing owner and evidence references.

The SDK rebuilds its base prompt through a resource loader. A session-owned
loader must preserve the resolved personality and explicit projection during
creation, tool exposure changes, and later prompt setup. A direct write to the
raw agent prompt alone can be overwritten. Conversation restoration continues
through Knoxx's existing composite message source. Durable encounters and
memory remain in existing scoped storage, not a file or sidecar invented by
this feature.

## Consumed intake settings and current account proof

The proposed EDN includes the concrete value to place under
`:agent :character-encounters` on both maker and reply resources. The source
resolver also supports the existing top-level fallback. Its shape is:

```clojure
{:sources [{:source {:kind "discord" :account-id "stable bot user identity"
                     :scope-id "an exactly admitted channel" :visibility :private}
            :tool-id "discord.channel.messages"
            :parameters {:channel_id "the same admitted channel"}
            :poll-mode :newest :limit 24}]
 :context {:max-encounters 6 :max-chars 12000 :excerpt-chars 1200
           :include-self-output? true}}
```

This example describes the shape; the proposal contains the actual nonsecret
identities. Initial intake covers the same seven current Discord read channels
and the current Bluesky account's timeline. Private Discord stays private.
Every source needs an enabled, actually resolvable canonical source resource,
selected through the existing source references, whose
`:source/filters :encounter-source` is the exact kind/account/space/visibility
tuple. The source's actor or credential owner must match the current actor,
its declared tool ceiling must permit the read, and current stored grants must
still permit it. A missing source reference, composed run/event override,
disabled source, revoked grant, different account, or missing credential
mapping cannot become authority. Admission and later recall recheck that
authority; retained admission evidence does not become a permanent grant.

Read-only current metadata inspection found the active existing actor's
Discord credential identifier equal to the verified bot user identity, and
its Bluesky identifier equal to the existing handle. Prior native publication
receipts identify that handle's stable DID. The proposal declares the exact
handle-to-DID mapping inside the canonical Bluesky source filter; it does not
alter credentials. Timeline/search projections additionally report the actual
authenticated session DID, and the adapter refuses a declared mismatch.
Self-output detection compares stable author identity to the bound account,
never a display name or prose claim.

The current reply contract otherwise denies timeline and memory calls and its
explicit ceiling omits `discord.channel.messages`. The proposal makes the
necessary narrow delta: add that canonical Discord read, `bluesky.timeline`,
`memory_search`, and `memory_session` to its ceiling; remove only the existing
timeline/memory denials; explicitly enable bounded scoped passive recall with
three results. Preserve every other denial and the current reply persona,
model, immediate incoming-message priority, maker independence, and ordinary
single-send/no-Bluesky-publication behavior. Its separate mode map contains
home reply, observation, memory, and bounded delegation. It does not inherit
the maker's production tool groups. An unchanged reply ceiling would refuse
all of the proposed retained source context, despite shared storage ownership.

The proposed observation cadence is every five minutes through the existing
schedule generator and event dispatcher. Add the proposed emitted event to
that generator and route its trigger to `:actions/character-intake`; no model
turn or publication is part of intake. The fifteen-minute creative opportunity
and immediate home-channel reply path remain independent. This proposed
cadence is not active until the host resources are applied.

Each pull admits at most 24 items. Bluesky always requests the newest page
again: a returned pagination token describes older material and is retained
only as coverage evidence. Newest Discord reads also overlap and deduplicate
retained identities, preserving later changes when they remain in the bounded
window. Optional Discord `:after` mode advances only when source count evidence
proves the short result was unfiltered; full, filtered, or unknown windows
hold their cursor. Snowflakes are compared without losing numeric precision.

Page coverage is retained in the existing checkpoint event with mode, reason,
fetched/admitted counts, overflow, provider continuation and source extrema.
These adapters always record `:complete? false`: a bounded newest window is
not complete history, and busy spaces can contain unobserved older items.
Coverage survives retry and a reconstructed store port. Partial admission does
not advance its cursor. Canonical source timestamps preserve millisecond
ordering and reject invalid calendar dates rather than replacing source time
with observation time.

Before each opted-in maker/reply decision, the runtime reloads authorized
encounters and attaches quoted data after the request and recall sections,
outside the system persona. External material can form the bounded query for
related scoped memory. Encounter IDs, causal source IDs and fresh inclusion
authorization are retained as turn evidence. This establishes a supported
input path; a changed model decision still needs natural runtime observation.

This first slice retains encounters durably but reloads only the recent bounded
candidate window: at most 48 rows per authorized source, then six context
entries by default. Selection gives external observations priority, orders them
by actual source time, and takes a first round across distinct exact source
scopes before additional entries from one scope. Retained, labeled self-output
can fill spare slots and character budget; it cannot displace available external
observations that fit those bounds. The fixed bound does not guarantee every
busy source appears in every decision or complete historical coverage.
Encounter events deliberately have no synthetic session
identity. Generic `memory_search` authorization filters sessionless results,
so scoped vector recall here retrieves existing session/action memory; it is
not arbitrary historical encounter retrieval. Lifelong encounter selection,
graph visibility, and physical mood/relationship field projection remain
separate unfinished work. Neither altered prose nor these fixtures proves
that those broader state mechanisms evolved.
